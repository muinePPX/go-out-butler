# 现场 API 确认清单

> 到现场第一天（8/4）优先确认以下 7 项。每项确认后，在对应节点文件中替换 `# 现场替换为:` 标注的 mock 实现。

## 确认优先级

按对演示的影响排序：机械臂 > 底盘导航 > 深度相机 > 语音 ASR > M-Claw > 软总线 > ROS1

---

## 1. 机械臂控制（最高优先级）

**为什么最优先**：这是场景的核心动作（抓取物品），没有它整个演示不成立。

**要确认的问题**：
- 机械臂控制方式：ROS 话题？专用 SDK？串口命令？
- 控制话题/函数名是什么？
- 如何控制抓取动作（关节角度？预设动作序列？逆运动学目标点？）
- 如何控制放置动作（放到包的位置）

**确认方法**：
```shell
hdc shell
run rostopic list 2>/dev/null | grep -i arm
run rostopic list 2>/dev/null | grep -i joint
run rostopic list 2>/dev/null | grep -i gripper
run rosnode list 2>/dev/null
run rosservice list 2>/dev/null | grep -i arm
```

**对应节点**：`nodes/arm_control.py` -> `grab()` 函数

**fallback**：打印 mock 日志 + 延时（已实现），演示时用流程说明配合

---

**要确认的问题**：

**确认方法**：
```shell

run rostopic list 2>/dev/null | grep -i depth
run rosnode list 2>/dev/null | grep -i camera
```

**对应节点**：`nodes/camera_perception.py` -> `perceive()` 函数

**fallback**：二维码扫描（纯 Python 二维码库），或打印 mock 日志

## 4. 语音 ASR / TTS

**要确认的问题**：
- 开发板有没有本地 ASR 能力？（NPU 6 TOPS 可推理）
- 能否联网调用云端 ASR（如百度、讯飞）？
- 有没有 TTS 语音合成能力？
- 麦克风硬件在哪？如何采集音频？

**确认方法**：
```shell
hdc shell
ls /dev/snd/ 2>/dev/null
run pip3 list 2>/dev/null | grep -i -E "speech|asr|tts|vosk|paddlespeech"
ps -ef | grep -i speech
ping -c 2 baidu.com 2>/dev/null
```

**对应节点**：`nodes/voice_input.py`（ASR）、`nodes/feedback.py`（TTS）

**fallback**：stdin 文字输入（已实现）。现场可加一个简单手机网页输入

## 7. ROS1 是否可用

**要确认的问题**：
- ROS1 (noetic) 是否已安装可用？
- 有没有 roscore？

**确认方法**：
```shell
hdc shell
run rosversion -d 2>/dev/null
run roscore --help 2>/dev/null | head -1
run rosnode list 2>/dev/null
```

**影响**：如果 ROS1 可用，机械臂和相机大概率通过 ROS 话题控制（参考第 1、3 项）

## 确认后的操作流程

每确认一项 API：

1. 在对应节点文件中找到 `# 现场替换为:` 注释
2. 用真实 API 替换 mock 函数实现
3. 保留 mock 作为 fallback（加 try/except 降级）
4. 推送到开发板测试：
   ```shell
   hdc file send nodes/xxx.py /data/local/robot/nodes/
   run dora reload <dataflow-id> --dataflow /data/local/robot/dataflow.yml
   ```
5. 验证该节点输出正常后，再替换下一个
